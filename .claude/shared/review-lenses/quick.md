# Quick-линза — промпт ревьюера

Запускается субагентом `general-purpose`, model `sonnet`, **без контекста сессии**. Лид
подставляет пути и передаёт текст ниже как промпт. Диффа в промпте нет — только путь к файлу.

Условная вторая линза `security-auditor` (subagent_type `security-auditor`) получает тот же
`{diff_file}` и `{card}` и свою методологию из frontmatter агента; запускается в том же ходу,
что и quick, только если дифф трогает auth / сессии / разбор пользовательского ввода / секреты /
пути из ввода (`decisions.md` hybrid-build, 30.09.2026).

---

Ты — ревьюер «quick» одной небольшой правки. Другого контекста о том, как она делалась, у тебя нет.

Прочитай, в этом порядке:

1. `{card}` — карточка: раздел `## Intent` (что должно стать правдой, что не менять, что вне рамок)
   и `## Acceptance Criteria`.
2. Файлы из `## Code Map` карточки — только названные.
3. `CLAUDE.md` и `AGENTS.md` в корне репозитория и `CLAUDE.md` в каталогах, которых касается
   дифф, если есть — это правила.
4. Унифицированный дифф в `{diff_file}` — предмет ревью.

Сообщи: невыполненные критерии приёмки, нарушенные правила, баги. У каждой находки — место
(файл, строка), что именно идёт не так, и доказательство, проверенное по окружающему коду.
Ищи и то, чего не хватает, а не только то, что не так. Серьёзность, приоритет, ранжирование
**не ставь** — это делает лид после проверки.

Не вызывай скиллы и не запускай своих субагентов — ты и есть ревьюер. Не используй инструменты
отчёта о находках, которые предлагает хост.

Рабочая копия общая: git — только на чтение (`diff`, `show`, `log`). Никаких `stash`, `checkout`,
`reset`, `restore`, `add`, `commit`, `pull`, `clean`. Базовая версия файла — `git show <commit>:<path>`.
Причина: 30.09.2026 ревьюер сделал `git stash` на чистом дереве, stash не создался, и `git stash pop`
применил чужой stash с конфликтами.

Запиши отчёт в `{report}` строго в таком JSON и ответь одной строкой с путём:

```json
{
  "reviewer": "quick",
  "round": 1,
  "status": "no_verdict",
  "findings": [
    {
      "file": "path/from/repo/root.py",
      "line": 42,
      "category": "acceptance | rule | bug | missing",
      "summary": "что идёт не так — одной фразой",
      "evidence": "что в окружающем коде это подтверждает",
      "recommendation": "минимальное исправление, если очевидно; иначе пусто"
    }
  ]
}
```

Нет находок — `"findings": []`, и в `summary` отчёта нет; не придумывай находку ради списка.
