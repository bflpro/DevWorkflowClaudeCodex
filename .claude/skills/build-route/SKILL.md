# build-route

Порог размера задан в `ENGINEERING.md` §1a и здесь не повторяется — раздел там главнее этого файла.
Шаги ниже исполняет основная сессия (лид). Субагенты — только разведка и ревью-линзы;
исполнителя в oneshot нет.

## Шаг 0. Clarify

1. **Намерение** — `$ARGUMENTS` как есть: фраза, ссылка на issue, путь к файлу. Файл — прочитать
   и взять содержимое как намерение; состояние из него не выводить. Пусто — спросить одной строкой.
2. **Git.** `git status --porcelain`. Свои незакоммиченные правки → HALT, спросить. Чужие файлы
   (общий чекаут, `.claude/scripts/README.md` «Общий чекаут») → запомнить для `--ignore` в квитанции,
   продолжить. Ветка явно не про это намерение → спросить.
3. **Одна цель.** Намерение распадается на ≥2 независимо поставляемых результата → показать
   список, предложить взять первый; остальные — строками в `work/quick-<slug>/deferred-work.md`
   (`- source: intent / summary / evidence`). Ветвь «сделать всё» — с оговоркой рисков.
4. **Уровень.** L0 или L1 по `ENGINEERING.md` §0; не сказано — L1. L2+ в oneshot не бывает.
5. **Тривиальность.** Опечатка, комментарий, `.gitignore`, форматирование — сказать, что `/build`
   не нужен, поправить напрямую и выйти.

## Шаг 1. Разведка

Один-два субагента `Explore` (`run_in_background: false`, ждать в этом ходу), с указанием
«вернуть только короткую сводку»: файлы и символы, которые придётся менять; что переиспользовать;
что не трогать; существующие тесты рядом; есть ли на пути запись наружу или серверный юнит.
Не спрашивать человека во время разведки — сначала репозиторий, история, документы проекта.
Не пересказывать разведку в чате: она уйдёт в Code Map карточки.

## Шаг 2. Порог

Применить условия `ENGINEERING.md` §1a к сводке разведки, оценку строк — «без дополнительного чтения,
с минимальным рассуждением». Результат записать дословно (это поле `sizing:` карточки).

- **Все условия выполнены → oneshot**, шаг 3.
- **Хотя бы одно нет → конвейер.** Создать папку `bash .claude/shared/scripts/init-feature-folder.sh <slug>`,
  записать сводку разведки в `work/<slug>/code-research.md` с пометкой «черновик /build, <дата>»,
  сказать одной строкой, какое условие не прошло, и предложить `/new-user-spec <slug>`
  (намерение не определено) или `/new-tech-spec <slug>` (определено: ясно, что должно стать
  правдой, что не менять, что вне рамок). Выйти.

Сомнение — в пользу конвейера. Оценку строк не занижать.

## Шаг 3. Карточка

1. `mkdir -p work/quick-<slug>/tasks work/quick-<slug>/logs/working/task-1 work/quick-<slug>/logs/receipts`.
   Слаг — kebab-case из намерения; есть номер issue — им начинается (`gh-47-fix-auth`).
   `work/quick-<slug>/tasks/1.md` уже есть со статусом `in_progress` → это та же работа, продолжить
   с шага 4; иначе — новый слаг с суффиксом `-2`.
2. Заполнить `references/plan-template.md` → `work/quick-<slug>/tasks/1.md`. Потолок — два экрана;
   не влезает → это не oneshot, вернуться к шагу 2 с вердиктом «конвейер».
3. **Открытые вопросы** — то, что разведка не решила и что решает человек: задать **одним
   сообщением**, нумерованно, с вариантами и смыслом каждого. Ответы записать в `Решения:` блока
   Intent. Пробел в Intent не заполнять допущением.
4. `start_commit: $(git rev-parse HEAD)` — до первой правки кода. Без него нет `owns-check` и квитанции.
5. `owns_paths` — только из разведки; `never_touch` не сужать.

Чекпоинта «утверди план» в oneshot нет: Intent заморожен ответами на вопросы (или их отсутствием).
После первой правки кода блок `<frozen-after-approval>` меняет только человек.

## Шаг 4. Реализация в этой сессии

- Правки только внутри `owns_paths`; ошибка сборки в чужом файле — сообщить, не чинить.
- TDD-lite: тест из `## TDD Anchor` до кода, где применимо.
- **Когда остановиться.** Если по ходу выяснилось, что в запросе не хватает того, что человек
  заметит в результате, — записать пробел в `## Implementation Notes` и спросить. Не догадываться.
- Линтер, форматтер, тесты по изменённым файлам; команды из `## Verification Steps`.
- **Prod Gate** (L1): самопроверка по минимуму `ENGINEERING.md` §2 и по сработавшим блокам
  `.claude/skills/prod-review/production-checklist.md` — только сработавшие, не файл целиком.
  Осознанный пропуск — в строку `Отложено:` закрывающего блока.
- Коммит кода: `feat|fix: <slug> — <что>` (тесты зелёные). Трейлер — по правилам коммитов проекта.

## Шаг 5. Quick-ревью

1. Дифф с `start_commit` включая неотслеживаемые файлы → `<scratchpad>/quick-<slug>.diff`
   (`git diff <start_commit> -- <owns_paths>` плюс `git ls-files --others --exclude-standard` по тем же путям).
2. Решить про вторую линзу: дифф трогает auth / сессии / разбор ввода / секреты / пути из ввода →
   `security-auditor` тоже. Сказать одной строкой, что запускается.
3. Запустить линзы **в одном ходу и дождаться** (`run_in_background: false`): промпт из
   `.claude/shared/review-lenses/quick.md` с подставленными `{card}`, `{diff_file}`,
   `{report}` = `work/quick-<slug>/logs/working/task-1/quick-1.json`
   (для security — `security-auditor-1.json`). Диффа в промпте нет, только путь.
   Слепое ревью: линза не получает `Implementation Notes`, decisions и рассказ исполнителя.

## Шаг 6. Триаж лидом

По `.claude/shared/review-lenses/triage.md`: каждая находка проверена в коде, вердикт + доказательство строкой в
`## Review Triage Log` карточки, группировка по корневой причине, маршрут `patch / ask / defer`.
Не больше двух циклов patch → перезапуск проверок.

Закрытие в механике находок — без правки скриптов:

1. `python3 .claude/scripts/findings-sync.py work/quick-<slug> 1` → в
   `logs/receipts/task-1/FINDINGS.md` появились отпечатки.
2. Записать `work/quick-<slug>/logs/working/task-1/quick-2.json`:
   `{"reviewer":"quick","round":2,"status":"triaged","findings":[],"closures":[…]}` — по одной
   записи на отпечаток: `{"fingerprint","verdict":"closed"|"open","evidence":"<вердикт триажа>: <доказательство>"}`.
   `closed` — для `patch` (после фикса), `false`, отброшенных `low` и `defer` (со ссылкой на
   `deferred-work.md`); `open` — только для `ask`, пока человек не ответил. Для второй линзы — то же
   в `security-auditor-2.json`. Это и есть «закрытие лидом с доказательством»: квитанция
   цитирует `FINDINGS.md`, а не слова.

## Шаг 7. Квитанция и завершение

1. `python3 .claude/scripts/task-accept.py work/quick-<slug> 1` (`--ignore-untracked` /
   `--ignore <путь>` для чужих файлов из шага 0). Exit 0 → `status: done` в карточке.
   Exit 1 → причины из вывода, починить, повторить; три неудачи → остановиться, статус
   `in_progress`, доложить. `acceptance.json` руками не править.
2. Коммит: `chore(quick-<slug>): receipt` — карточка, `logs/receipts/`, `deferred-work.md`.
   `logs/working/` в `.gitignore`, не добавлять. Без push.
3. Ответ человеку — коротко: что изменилось; итог ревью и что отложено; хеш коммита; для L1 —
   закрывающий блок `Риски:` / `Отложено:` / `Наблюдаемость:` (`ENGINEERING.md` §6.5).
   Файлы не перечислять, план не пересказывать.

## Что не делать

- Не спавнить исполнителя: oneshot — работа лида.
- Не запускать thorough-набор линз, аудит-волну, QA и деплой-волну: это конвейер спек.
- Не трогать `acceptance.json`, `findings/*.json` руками.
- Не переводить в `done` по словам, зелёному выходу или «ревьюер согласился».
