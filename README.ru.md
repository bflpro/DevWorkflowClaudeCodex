# DevWorkflowClaudeCodex

[English](README.md) · **Русский**

Процесс разработки для Claude Code и Codex, который ставится в любой репозиторий: от идеи
через спецификации и задачи к коду, ревью и приёмке. Каждый шаг закрыт проверкой, которую
делает скрипт, а не слово модели: задача считается готовой только по квитанции, исполнитель не
может выйти за свои файлы, ревьюер не видит рассказа исполнителя о том, «как всё хорошо».

## Поток работы

```
/build <задача> ── разведка кода ── порог (ENGINEERING.md §1a)
   │                                   │
   │ ≤100 строк, ≤5 файлов,            │ иначе
   │ без записи наружу, L ≤ 1          ▼
   ▼                         /new-user-spec   интервью → work/<feature>/user-spec.md
 oneshot: карточка,          /new-tech-spec   архитектура, решения, критерии с verify-командами
 код, одна ревью-линза,      /decompose-tech-spec  карточки задач: owns_paths, reads, TDD Anchor
 квитанция                   /do-feature      волны агентов:
                                                wave-check.py   задачи волны не пересекаются
                                                код + тесты (TDD)
                                                ревью-линзы, триаж находок
                                                task-accept.py  перезапуск verify, owns-check,
                                                                открытые находки → квитанция
                             /done            критерии из техспека перезапускаются как квитанции,
                                              footprint сверяется с git diff, доки обновляются
```

Рядом с потоком работают:

- **рефлексы** — хук `PreToolUse` подмешивает урок прямо перед опасной командой (`git add`
  с данными рантайма, массовая операция, cron без лока);
- **`/prod-review`** — чеклист продакшн-готовности (блоки A–J: таймауты, идемпотентность,
  вебхуки, локи, рост данных, LLM-фичи);
- **скиллы документации** — `technical-writing` и профильные (дизайн-доки, ранбуки, ADR,
  постмортемы), `/prose-review`, `/ground-docs`.

## Установка

Требуется: `git`, `python3` ≥ 3.11 с PyYAML (`python3 -m pip install pyyaml`, им читают карточки задач гейты), `node` (для хуков-рефлексов).

```bash
git clone https://github.com/bflpro/DevWorkflowClaudeCodex.git
cd DevWorkflowClaudeCodex
./install.sh --target /путь/к/проекту            # Claude Code
./install.sh --target /путь/к/проекту --codex    # + Codex
```

Флаги: `--dry-run` показывает, что будет сделано, ничего не меняя; `--force` заменяет
изменённые вами файлы (оригиналы уходят в `.workflow-backup/<время>/`).

После установки откройте проект в Claude Code и запустите `/build <задача>` или
`/new-user-spec`. В Codex — новая сессия, доверить проект, проверить `/hooks`, вызывать
`$source-command-build`.

## Что ставится в проект

| Путь | Что это |
|---|---|
| `.claude/skills/` | методики: планирование, спеки, декомпозиция, исполнение фичи, код, ревью, тесты, QA, prod-review, документация |
| `.claude/agents/` | субагенты: валидаторы спек и задач, ревьюеры кода, тестов, безопасности, QA |
| `.claude/commands/` | slash-команды из таблицы в `templates/CLAUDE.md` |
| `.claude/shared/` | шаблоны артефактов фичи, интервью, ревью-линзы, скрипт создания папки фичи |
| `.claude/scripts/` | гейты: `task-accept.py`, `owns-check.py`, `wave-check.py`, `findings-sync.py`, `check-readme.py`, `check-techspec-readiness.py`, движок рефлексов |
| `.claude/reflexes/` | рефлексы — короткие уроки с условием срабатывания |
| `.claude/settings.json` | два хука: рефлексы и восстановление контекста после сжатия; в существующий файл хуки **дописываются** |
| `CLAUDE.md`, `AGENTS.md`, `ENGINEERING.md` | правила проекта — только если их ещё нет |
| `.codex/`, `.agents/skills/` | с `--codex`: адаптер и сгенерированные входные точки |
| `.gitignore` | `work/*/logs/working/`, `.codex/data/`, `.workflow-backup/` |

`ENGINEERING.md` содержит разделы «заполнить» (стек, деплой) — заполните их под свой проект:
на остальные разделы по номерам ссылаются скиллы, нумерацию не меняйте.

## Почему так

- **Ставится в проект, а не в `~/.claude`.** Скиллы и гейты вызывают `.claude/scripts/…` и
  `.claude/shared/…` от корня проекта, и методика едет вместе с репозиторием: у коллеги после
  `git clone` тот же процесс. Глобальная установка ломала бы эти пути на чужой машине.
- **Одна методика на два инструмента.** Codex не получает копию скиллов: генератор
  `.codex/sync-workflow.py` пишет короткие входные точки, которые читают оригинал из `.claude/`.
  Копии расходятся; ссылки — нет. Хеши в манифесте ловят ручную правку и устаревание.
- **Готовность — по квитанции.** Отчёт исполнителя и зелёный выход процесса — не доказательство;
  `task-accept.py` сам перезапускает проверки и пишет `acceptance.json`.
- **Повторная установка безопасна.** Отвергнут вариант «перезаписать всё»: он стирал бы ваши
  правки скиллов.

## Инварианты

- `install.sh` никогда не заменяет изменённый вами файл без `--force`, и при `--force` сначала
  делает резервную копию; `CLAUDE.md`, `AGENTS.md`, `ENGINEERING.md` не трогает, если они есть.
- Повторный запуск без изменений сообщает `added 0` и ничего не меняет.
- Генератор Codex ничего не удаляет и не перезаписывает отредактированные вручную входные точки.
- Ничего не отправляется в сеть: установщик, гейты и хуки работают только с локальными файлами.

## Обновление

```bash
cd DevWorkflowClaudeCodex && git pull
./install.sh --target /путь/к/проекту [--codex]
```

Файлы, которые вы не меняли, обновятся; изменённые останутся вашими и будут перечислены —
сравните их с новой версией и перенесите нужное (или `--force`). С `--codex` после обновления
входные точки перегенерируются.

## Как проверить и как понять, что сломалось

```bash
bash .claude/scripts/check-setup.sh            # хуки, интерпретаторы, скрипты на месте
python3 .codex/sync-workflow.py --check        # входные точки Codex соответствуют .claude/
```

- `/new-user-spec` пишет `template not found` — неполный `.claude/shared/`; переустановите.
- Рефлексы не срабатывают — нет `node` или хуки не попали в `.claude/settings.json`
  (`check-setup.sh` покажет).
- `workflow-sync: drift=N` — правили `.claude/`, а входные точки не перегенерировали:
  `python3 .codex/sync-workflow.py --write`. `Edited target` — входную точку правили руками.
- У задачи `status: done`, а `logs/receipts/task-N/acceptance.json` нет — гейт обошли.

## Разработка самого workflow

```bash
bash tools/check-clean.sh                                              # сторож утечек
python3 -m unittest discover -s .claude/scripts/tests -t .claude/scripts/tests
python3 -m unittest discover -s .codex -p 'test_*.py'
python3 .codex/sync-workflow.py --check
```

То же гоняет CI (`.github/workflows/check.yml`) вместе с пробной установкой в пустой репозиторий.
Изменили скилл, команду или агента — перегенерируйте входные точки Codex (`--write`) тем же коммитом.
