# AGENTS.md

Инструкции для агентов, которые читают `AGENTS.md` (Codex CLI, Codex в IDE и подобные).
Правила проекта живут в `CLAUDE.md` и `ENGINEERING.md`; этот файл делает их видимыми для
инструментов, которые `CLAUDE.md` не читают. При расхождении побеждает `CLAUDE.md`.

## Прочитать до первой правки

| Файл | Зачем |
|---|---|
| `CLAUDE.md` | правила проекта, структура, команды workflow |
| `ENGINEERING.md` | уровни зрелости L0–L3, маршрут по размеру, Prod Gate, квитанции |
| `<компонент>/README.md` | как устроен компонент, прежде чем его менять |

## Неснижаемый минимум

1. **Секреты — только в `.env`.** Не коммитить и не печатать. Нашёл секрет в коде — сказать сразу.
2. **Читать перед записью.** Не перезаписывать вслепую, не удалять файлы без подтверждения.
3. **План до кода** для нетривиальных задач; размер процесса — по `ENGINEERING.md` §1a.
4. **Уровень зрелости — до кода** (`ENGINEERING.md` §0), по умолчанию L1. Решения уровня
   выше текущего не тащить в код.
5. **Prod Gate для L1+** (`ENGINEERING.md` §2): таймауты, ограниченные ретраи с backoff,
   идемпотентная запись наружу, дедуп вебхуков, лок cron, состояние не в памяти процесса,
   нет секретов и ПДн в логах, рост ограничен, есть метрика поломки.
6. **Готовность задачи — квитанция.** `status: done` только после
   `python3 .claude/scripts/task-accept.py work/<feature> N` с exit 0. Исполнитель правит только
   пути из `owns_paths`; перед волной — `wave-check.py`.
7. **README — часть результата**; поведение изменилось — README правится тем же коммитом.
8. **Закрывающий блок для L1+:** `Риски:` / `Отложено:` / `Наблюдаемость:`.
9. **Verify, don't guess.** Не выдумывать имена функций и параметры.

## Workflow в Codex

До выполнения workflow прочитай `.codex/workflow.md`: это адаптер инструментов и авторизации.
Методики, шаблоны и критерии ревью живут в `.claude/`; Codex читает их через входные точки
`.agents/skills/` и `.codex/agents/`. Отдельных копий методик нет.

- **Команды:** `$source-command-build`, `$source-command-new-user-spec`,
  `$source-command-new-tech-spec`, `$source-command-decompose-tech-spec`,
  `$source-command-do-task`, `$source-command-do-feature`, `$source-command-review`,
  `$source-command-verify`, `$source-command-prod-review`, `$source-command-done` читают
  актуальные `.claude/commands/*.md`. Slash-запросы в стиле Claude маршрутизируй к ним.
  `Skill(...)` в исходнике означает чтение `.claude/skills/<name>/SKILL.md`.
- **Синхронизация:** после правки `.claude/skills/`, `.claude/commands/`, `.claude/agents/`
  запусти `python3 .codex/sync-workflow.py --check`, затем после просмотра диффа — `--write`.
- **Рефлексы:** `.codex/hooks.json` подключает тот же движок `.claude/reflexes/`. Нужны
  доверенный проект и включённые hooks; проверяй через `/hooks`.
- **Авторизация:** запуск скилла сам по себе не разрешает субагентов, коммит, деплой или
  запись наружу. Без явного разрешения на делегирование выполняй этапы сам и называй
  самопроверку самопроверкой, а не независимым ревью.
